## Закрыты два пункта одной группой — Linux `register_service()` и `Cargo.toml`

**Linux `register_service()`** больше не `todo!()`. Ключевое решение: подстановка через **точную строковую замену**, не regex — юнит содержит `/opt/agent-connector` буквально несколько раз (подтверждено предыдущим чтением реального файла), простой `.replace()` покрывает все вхождения корректно. Для дефолтного случая (`--prefix`/`--user` не заданы) юнит копируется **буквально без единой подстановки** — это безопаснее, чем прогонять замену через файл, который уже соответствует нужным значениям.

**Важное разделение путей**, которое легко перепутать: `ServiceContext.working_directory` — это install-prefix (`/opt/agent-connector`, куда копируются файлы), а сам файл-шаблон `deploy/systemd/adapterd.service` лежит в **repo checkout**, откуда запускается `adapterctl`. `find_repo_root()` явно это разделяет через `std::env::current_dir()`, не через `prefix`.

**`geteuid()` без внешнего `libc` crate** — минимальный `extern "C"` FFI на одну функцию, чтобы не тащить полноценную зависимость только для проверки root. Компромисс, но обоснованный для одной проверки.

## `Cargo.toml` — честно зафиксированные технические долги, не скрытые

Три момента, которые нашёл при проверке актуальных версий через веб-поиск и явно задокументировал, а не тихо проигнорировал:

**`serde_yaml` официально deprecated** — автор не планирует новых релизов. Используется здесь **только потому**, что `adapterd-config` уже на нём завязан; смена парсера должна происходить синхронно в обоих крейтах, не тихой заменой в одном.github+1

**`atty` имеет известный unsound-репорт** (RUSTSEC-2021-0145) на Windows для redirected handles — годится для MVP, но зафиксирован как TODO на замену на `is-terminal` до релиза.

**`bollard 0.17`** подтверждён как актуальная версия с нативной поддержкой Windows named pipes — совпадает с тем, что я уже использовал в `managed_docker.rs`.[docs](https://docs.rs/bollard/latest/bollard/?search=Driver)

Четыре теста проверяют именно то, что легко сломать при рефакторинге: полное отсутствие старого prefix после замены, замену **только** `User=`/`Group=` строк (не порчу остального текста), и сохранность структуры `[Unit]`/`[Service]`/`[Install]` секций.
