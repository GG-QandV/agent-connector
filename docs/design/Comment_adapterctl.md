Готова упрощённая версия — English-only, с архитектурной заглушкой, которая делает будущее расширение до 25-40 языков бесшовным, не требуя переписывания вызывающего кода.

Ключевое решение: сигнатура Cow<'static, str>, не &'static str
Это единственная деталь, которую стоило заложить заранее, несмотря на отказ от полноценного i18n сейчас. Настоящий Fluent/ICU MessageFormat backend почти всегда возвращает owned String (интерполяция плейсхолдеров типа "порт {port} занят", плюрализация "1 файл" vs "5 файлов") — не статичный слайс. Заложив Cow сразу, я избегаю ситуации, когда через полгода при добавлении реального i18n пришлось бы менять тип возвращаемого значения и, соответственно, весь вызывающий код в install_flow.rs.

Что осталось неизменным, что изменилось
Сам enum Msg с exhaustive-match подходом и принцип "install-логика никогда не содержит текстовых строк напрямую" — не изменились, потому что это верно независимо от количества языков. Изменилось только внутреннее тело render(): убрал русский вариант и параметр Lang, оставил один match на английском.

Секция FUTURE — зафиксированный план, не реализация
Явно расписал в комментариях, что нужно не делать сейчас, а что предусмотреть архитектурно: файлы переводов в locales/{lang}/*.ftl (не Rust-код, чтобы переводчики могли контрибьютить без пересборки), тот же самый механизм определения языка через --lang/ADAPTERCTL_LANG/LC_ALL цепочку из отменённой версии — он остаётся валидным на будущее, просто отложен. Триггер для реализации — явный запрос от реальных пользователей, не "на будущее", это прямое применение YAGNI: стоимость поддержки N языков растёт с каждым новым CLI-сообщением, а не только на старте, так что откладывать до реального сигнала — правильно.
