## Прямой ответ: `crates/adapterctl/tests/managed_docker_integration.rs`

Это стандартная Rust-конвенция — `cargo` автоматически компилирует любой `.rs` файл в директории `tests/` на уровне крейта как отдельный интеграционный тест-бинарь, без правок `Cargo.toml`. Не нужно создавать отдельный workspace member или усложнять CI-матрицу лишним крейтом, существующим только для тестов.

## Почему именно так, а не иначе

**`#[ignore]` — критичная деталь.** Без него обычный `cargo test --workspace` на CI без Docker или на машине контрибьютора без Docker Desktop начал бы падать на этих тестах, что заблокировало бы всех, кто не работает с этим конкретным путём кода. С `#[ignore]` тест физически существует в репозитории, виден любому, кто читает код, но требует явного `cargo test -- --ignored`, чтобы реально запуститься.

**Изоляция от продовых имён ресурсов.** Тестовый прогон использует `TEST_ADAPTER_CONNECTOR_PG_DSN` и одноразовый `plan()`, отдельный от `agent-connector-pg`/`agent-connector-pg-data`, которые уже могли быть созданы реальным `adapterctl install` на той же машине разработчика — тест не должен случайно затронуть уже установленную локальную инсталляцию.

## Первый прогон конкретно на macOS

1. Добавить `testcontainers`/`testcontainers-modules` в `[dev-dependencies]` — этого пакета в проекте пока нет вообще, я явно выделил diff в комментарии сверху файла.
2. Убедиться, что Docker Desktop запущен **и переключён в Linux containers mode** — тест первым шагом вызывает `preflight_check()`, ту же проверку, что делает сам installer, чтобы дать понятную ошибку вместо непонятного таймаута на `create_container`.
3. Запуск: `cargo test -p adapterctl --test managed_docker_integration -- --ignored`.

## Что оставлено честно недописанным

Второй тест (`managed_docker_rejects_foreign_resource_with_same_name`) — структурный каркас с `todo!()`. Он должен проверять правило #9 ("не трогать чужие Docker-ресурсы") под **реальным** daemon, не только юнит-тестом на моке, как было раньше. Полная реализация требует прямого `bollard`-кода для создания "чужого" контейнера без ownership label — оставил это явным `todo!()`, а не притворился, что тест готов, когда он не проверяет заявленный сценарий целиком.
