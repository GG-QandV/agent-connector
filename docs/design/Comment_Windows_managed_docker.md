Готова полная реализация managed_docker::ensure_running() через bollard, с named pipe для Windows и unix-socket для остальных платформ — код общий, разница инкапсулирована в одной функции connect().

Ключевое исправление контракта с adapterd
Обнаружил важную деталь при повторной сверке: StorageConfig::Postgres { dsn_env: String, ... } — adapterd читает DSN по имени переменной окружения, указанному в adapter.yaml, а не напрямую из YAML. Значит ManagedPostgresPlan теперь несёт dsn_env_var_name — installer пишет сам секрет в .env под этим именем, а в adapter.yaml попадает только имя переменной, не значение. Это важно: секрет никогда не оказывается в конфиг-файле, который потенциально может закоммититься или засветиться в дампах.

Новый защитный механизм — ownership label, не только имя
Каждый созданный ресурс (network, volume, container) получает label io.agent-connector.managed=true. Перед любой mutating операцией на ресурсе с совпадающим именем — ensure_network/ensure_volume/ensure_container и симметрично remove_all_resources — код проверяет и имя, и label. Если имя совпадает, но label нет, возвращается DockerError::NotOurResource вместо тихого переиспользования или, хуже, удаления чужого контейнера. Это усиливает правило #9 сверх того, что я предлагал ранее — раньше проверка была только по имени, что теоретически уязвимо, если кто-то случайно назвал свой контейнер agent-connector-pg.

wait_for_ready — важная деталь, которую легко упустить
Контейнер running ≠ Postgres готов принимать соединения — при первом запуске initdb может занять несколько секунд. Реализовал polling через docker exec pg_isready внутри контейнера (не прямой TCP-connect снаружи) — это работает одинаково независимо от того, опубликован ли host_port (в --docker-network-only режиме прямого TCP доступа снаружи вообще нет).

Тесты для регрессии
Пять юнит-тестов покрывают именно те инварианты, которые легко случайно сломать при будущем рефакторинге: отказ без --confirm-docker, отсутствие host port в network-only режиме, 127.0.0.1 (не 0.0.0.0) как дефолтный bind, пароль длиннее старого статичного adapter/adapter, и зафиксированный (не latest) тег образа.
